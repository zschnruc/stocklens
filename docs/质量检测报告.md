## 一、已证实的问题

### P1-1 `getQuoteBatch` 缺少超时控制 ✅ 已修复（2026-11-16）
**位置**：`src/js/10-api.js` 315-337 行
**现状**：`getQuote` 有 12s AbortController 超时，而 `getQuoteBatch` 的 `fetch` 裸调用无超时、无 abort。首页自选行情（`loadWatchQuotes`）依赖该函数，网络挂起时 Promise 长期悬空，自选价格一直显示骨架屏。
**修复**：
```js
chunks.map(async (chunk) => {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), 12000);
  try {
    const res = await fetch(API.quote + chunk.map(encodeURIComponent).join(','),
      { signal: ctrl.signal, cache: 'no-store' });
    // ...
  } finally { clearTimeout(timer); }
})
```

### P1-2 `getNews` 绕过东财限流队列 ✅ 已修复（2026-11-16）
**位置**：`src/js/10-api.js` 709 行
**现状**：`const data = await jsonp(url, ...)` 直接调用，未走 `emJsonp`（emQueue 串行 + 280ms 最小间隔）。其余全部东财接口（研报/财务/公司资料/板块）均走队列。与 PRD NFR-3"东方财富接口串行 + 最小间隔限流"不一致，高频时同样可能被限流。
**修复**：改为 `const data = await emJsonp(url)`；若确认 search-api-web 域名策略不同不受此限，则在代码处补注释说明例外原因。

### P1-3 周/月 K 视图会被评分刷新强制重置回日 K ✅ 已修复（2026-11-16）
**位置**：`src/js/50-main.js` 354-367 行（refreshScore）+ `src/js/31-render-analysis.js` 353 行
**现状**：`refreshScore()` → `renderOverview(score, state.core.kline)`（恒为日线）。用户切到周K/月K后，若点"研报/财务重试"（`retrySection` → `markCoreSettled` → 四项已齐 → `refreshScore`），图表被重绘回日K，用户所选周期丢失。
**修复**：`refreshScore` 中改为
```js
const k = state.periodKlines[state.klinePeriod] || state.core.kline;
renderOverview(score, k);
```
（`switchKlinePeriod` 已把各周期缓存在 `state.periodKlines`，直接复用即可。）

### P1-4 热门股行情未复用批量接口 ✅ 已修复（2026-11-16）
**位置**：`src/js/30-render-home.js` 225-238 行
**现状**：`loadHotQuotes` 对 6 只热门股各发一个 `getQuote` 请求（各自独立缓存写），而同文件的 `loadWatchQuotes` 已用 `getQuoteBatch` 一次拉取。首页打开即产生 6 个请求，为必要值的 6 倍。
**修复**：改用 `getQuoteBatch(HOT_STOCKS.map(s => s.quoteKey))`，并逐条回填 `cached('quote:'+key)` 的内存缓存，避免与 `getQuote` 缓存口径不一致。

### P2-5 `fmtBig` 死代码
**位置**：`src/js/00-utils.js` 120 行
**现状**：`${unit === '亿' ? '' : ''}` 两个分支相同，属无效表达式。
**修复**：删除该三元，直接 `${(n / 10000).toFixed(2)}万亿`。

### P2-6 `searchMemo` 只增不减
**位置**：`src/js/10-api.js` 102、186 行
**现状**：TTL 判断存在，但过期条目从不删除，Map 随搜索次数线性增长（单次会话影响小，长会话场景缓慢泄漏）。
**修复**：未命中 TTL 时顺手 `searchMemo.delete(q)`，或限制 Map 最大 50 条 LRU。

### P2-7 K 线 SVG 文字随容器拉伸变形
**位置**：`src/js/21-charts.js` 412 行（`preserveAspectRatio="none"`）
**现状**：svg 视口固定 660×312 且禁用等比缩放，容器更宽时日期/价格刻度、目标价标签文字被横向拉长变形。
**修复**：最简方案在 CSS 中限制 `.candle-wrap { max-width: 990px; margin: 0 auto; }` 控制拉伸比例上限。

### P2-8 `state.profileReady` 未在初始 state 中声明
**位置**：`src/js/50-main.js` 6-25 行（无此字段）、221 行动态赋值
**现状**：运行时才挂到 state 上，与"字段先行声明"的写法不一致。
**修复**：在 state 初始对象中补 `profileReady: false,`。

### P2-9 纯数字输入 1–5 位一律解析为港股
**位置**：`src/js/10-api.js` 209-212 行
**现状**：输入 `30075`（可能想搜 A 股 300750 打漏一位）会被无提示解析为港股 00375。
**修复**：在 `submitSearch` 中当命中为港股且原始输入为 4–5 位数字时，toast 提示"已按港股代码 00375 解析"，给用户纠正机会。

### P2-10 localStorage 缓存写入失败完全静默
**位置**：`src/js/00-utils.js` 237-241 行（writeLocal catch{}）
**现状**：K 线（320 根×多周期）等大对象可能超出配额持续写入失败，无任何观测手段。
**修复**：catch 中首次失败时 `console.warn('[StockLens] 本地缓存写入失败（可能超出配额）')`，仅告警一次，不影响功能。
